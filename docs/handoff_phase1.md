## 摘要

本题要求在 **4K 实拍低质量图（LQ）** 上做分辨率不变的 Diffusion 增强，并与 Ground Truth（GT）对齐计分；同时禁止内容编造。第一阶段完成三件事：（1）对官方验证集 5 对做内容与退化结构分析；（2）按「是否 Diffusion、是否从 LQ 起步、4K×8 GB 可迭代、文字/几何幻觉风险」筛选开源方案；（3）在本机实现并复测一条可运行的条件 DDPM 基线。

主要结果如下。

1. **验证集分数结构极不均匀。** LQ→GT 均值 PSNR / SSIM 为 **28.034 / 0.778**。五张图中，密叶（case4）为 18.056 / 0.309，海鸟（case3）为 35.622 / 0.935。均值几乎被 case4 的均方误差主导；case3 已接近 GT，继续增强的边际收益为负的概率高。
2. **本地 Lite 条件 DDPM 单独输出劣于 LQ。** 裸模型均值 **27.649 / 0.742**（相对 LQ：−0.386 dB / −0.035 SSIM），case3 单张掉 **1.235 dB**。该权重仅在合成几何图上短训，对实拍模糊与彩边无对应先验，反向过程引入的是高频颗粒而非复原细节。
3. **残差限幅融合（fidelity fuse）能把输出拉回 LQ 邻域。** 定义 \(y = x + \alpha\,\mathrm{clip}(\hat{x}-x,-\Delta,\Delta)\)，\(\alpha=0.25,\Delta=12\) 时，内存评测为 **28.004 / 0.776**；经 JPEG 写出后的端到端 `infer.py` 为 **27.982 / 0.775**（相对 LQ：−0.052 dB）。增大 \(\alpha\) 或叠 LAB 色彩对齐、高通结构锁均使均值下降。
4. **OSEDiff 已在本机官方验证集出分。** 裸模型均值 **23.216 / 0.740**（相对 LQ：−4.82 dB），文字与海鸟跌幅最大。同一套输出再经 `fuse`（\(\alpha=0.25,\Delta=12\)）后为 **28.030 / 0.781**（相对 LQ：−0.004 dB / +0.003 SSIM）。速度 **28.9 s/张**，峰值显存 **3.03 GB**。SeeSR / DiffBIR / SUPIR 仍未跑；`sd-turbo` 权重未装完。

本地 PSNR / SSIM 不是官方总分（公式入围后公布），本报告只把它们当作 **保真哨兵**：明显掉分几乎总对应噪声或结构漂移；不掉分也不等于观感更好。

**关键词**：可控图像增强；条件扩散；4K 分块推理；保真–生成权衡；OSEDiff；验证集偏差

## 1. 问题定义

### 1.1 任务

对挑战性实拍做高质量、可控增强。官方点名的五类元素为：小人脸、文字、密集绿植、钟表、鸟类。约束同时成立：

| 约束 | 含义 |
| --- | --- |
| 架构 | 必须是 Diffusion / AIGC，不能用传统滤波交差 |
| 分辨率 | 输入输出尺寸一致。官方图为 \(4096\times3072\) 或 \(3072\times4096\)，约 12.58 MP。本题不是 \(4\times\) 超分 |
| 内容一致 | 不增删物体、不改字、不换脸、不改指针几何 |
| 计分 | 与 GT 的接近程度；组委会另做主观审核，指标虚高但看起来不像原图可取消资格 |
| 工具 | 禁止 Photoshop、美图及豆包 / 通义 / ChatGPT / 华为图库等商用 API |

作品名 **keepsharp** 对应上述双目标：提高锐度（sharp），同时把内容锁在原图邻域（keep）。它是对约束的概括，不是对当前基线质量的断言。

### 1.2 本阶段范围

本阶段测量与分析限于：

- 官方验证集 5 对的内容标注、LQ–GT 距离、后处理消融；
- 文献与公开实现层面的方案筛选（OSEDiff / SeeSR / DiffBIR / SUPIR / SD-Turbo）；
- 一条满足「Diffusion + 8 GB 可跑 + 分辨率锁定」的本地基线（Lite DDPM + 分块 + 残差限幅）；
- OSEDiff（官方 LoRA + SD 2.1-base，场景 prompt 代替 RAM/DAPE）在同一 5 对上的 PSNR / SSIM / 秒/张 / 显存。

**未覆盖**：RAM/DAPE 官方 caption 协议下的 OSEDiff；SeeSR / DiffBIR / SUPIR / SD-Turbo 本机出分；测试集 100 张场景标注与官方提交；人脸专项（验证集中无小人脸样本）。

### 1.3 方法学限制（先于结果）

\(n=5\) 的验证集不能支持统计显著性检验，也不能代表测试集分布。用这 5 对 GT 微调后再在同一集合上报分，属于训练集–测试集泄漏，数字失去外推意义。下文所有「优于 / 劣于」仅描述这 5 张上的观测，不推广为官方名次。

## 2. 数据与评测协议

### 2.1 官方数据（本机，不在仓库）

官方图像不进入本仓库。测量时本机按 `configs/default.yaml` 放置，文件名为：

```text
验证集：case{1–5}_lq.jpg 与 case{1–5}_gt.jpg
测试集：case{1–100}.jpg
```

| 集合 | 数量 | 分辨率 | 体积（约） |
| --- | --- | --- | --- |
| 验证集 LQ+GT | 5 对 / 10 文件 | 与测试集同量级 | 16 MB |
| 测试集 LQ | 100 | 71 张 \(4096\times3072\)，29 张 \(3072\times4096\)，均为 12.58 MP | 0.20 GB |

配对规则：`pair_key()` 将 `case1_lq` 与 `case1_gt` 收成一对；写出文件名为 `case1.jpg`，不是 `case1_lq.jpg`。验证集与测试集都使用 `case1`… 这种 stem，但 **图像内容不同**。

### 2.2 对照定义

科学下限定义为 **未经处理的 LQ 对 GT** 的 PSNR / SSIM。记为「LQ」。

曾观测到：把 LQ 再做一遍 LAB 统计对齐后再当对照，均值 PSNR 从 28.034 降到约 27.92。对齐改变的是颜色矩，不是复原质量，不能当作下限。`identity` 后端若再叠加色彩匹配，也不再等于该下限。

PSNR 使用 8-bit 峰值 255：

\[
\mathrm{PSNR} = 10\log_{10}\frac{255^{2}}{\mathrm{MSE}},\qquad
\mathrm{MSE}=\frac{1}{3HW}\sum_{c,i,j}\bigl(y_{c,ij}-\hat{y}_{c,ij}\bigr)^{2}.
\]

SSIM 为仓库评测脚本的默认实现。另有一个非官方加权标量 `unofficial_score`（端到端报告中为 0.673），**不是**组委会公式，本报告不以其排序。

### 2.3 测量环境与流水线参数

| 项 | 取值 |
| --- | --- |
| GPU | RTX 4060 Laptop 8 GB |
| 分块 | `tile_size=512`，`overlap=64`，Hann 融合；短边 \(\ge 768\) 才分块 |
| Lite | \(T=50\)，DDIM 12 步，`base_channels=32`；本机权重见 `weights/README.md` |
| 保真融合 | \(\alpha=0.25\)，\(\Delta=12\) |
| LAB 色彩对齐 | 关闭 |

横图 \(4096\times3072\)、步长 \(512-64=448\) 时，网格为 \(9\times7=63\) 个 tile。整图一次进 8 GB 会超出显存，本阶段全部测量均在分块开启下完成。

## 3. 验证集内容与分数结构

五张图均经原图核对。LQ→GT 数字来自 `fidelity_ablation.json` 的 `raw_lq`。

| ID | 画面 | 退化（目视） | LQ PSNR | LQ SSIM | 对应 MSE |
| --- | --- | --- | --- | --- | --- |
| case1 | 印刷中文试卷，纸面偏粉 | 糊、噪、彩边、色偏 | 32.029 | 0.948 | 40.8 |
| case2 | 书架，中英文书脊混排 | 虚焦，书脊小字糊 | 28.189 | 0.831 | 98.7 |
| case3 | 滩涂海鸟（红嘴、湿泥） | 轻噪，羽轻微糊 | 35.622 | 0.935 | 17.8 |
| case4 | 密叶 + 粉花 | 接近油画糊 | 18.056 | 0.309 | 1017 |
| case5 | 建筑罗马钟，指针约 4:55 | 糊、JPEG 块 | 26.276 | 0.864 | 153.3 |

MSE 由 PSNR 反推：\(\mathrm{MSE}=255^{2}/10^{\mathrm{PSNR}/10}\)。case4 的 MSE 约为 case3 的 **57 倍**，约为其余四张 MSE 之和（310.6）的 **3.3 倍**。五张等权平均时，**均值 PSNR 的可提升空间主要落在 case4**。

反过来，case3 的 LQ 已与 GT 相距 17.8 的均方误差。任何会改变羽毛或泥地高频统计的生成步骤，都更容易增大误差而不是减小误差。case1 的 SSIM 0.948 说明结构已经高度对齐，错误模式将是笔画级幻觉，而不是整体模糊。case5 的可辨对象是罗马数字与指针角，属于几何约束，不是纹理合成问题。

验证集 **没有小人脸**。人脸是官方考点，但本集合无法检验身份保持。测试集文件名同样为 `case1`…`case100`，与上表无对应关系。

配置里对验证集 stem 的人工场景标签为：

```text
case1, case2 → text
case3 → bird
case4 → plant
case5 → clock
```

这是对这 5 张内容的标注，不是测试集分类器的输出，也不能按同名 stem 迁移。

## 4. 开源方案：机制分析与筛选

比较维度四条，全部来自本题约束而非偏好：

1. **是否 Diffusion**（硬性）。
2. **生成起点**：从随机噪声 \(x_T\sim\mathcal{N}(0,I)\) 出发，还是从 LQ 的加噪版本 / 潜变量出发。前者把「编造」写进采样过程。
3. **计算图是否适合 12.58 MP × 8 GB 日常迭代**。一张图 63 tile；步数与 UNet 宽度近似相乘。
4. **语义条件会不会改写文字与钟表几何**。RAM / 标签 / 高 CFG 文生图先验在印刷体和罗马数字上有已知的「写对语义、写错字形」倾向。

SeeSR / DiffBIR / SUPIR 的排除仍是机制判断，未经本机出分。OSEDiff 已在 2026-09-03 用官方 5 对测量，协议见第 6.6 节。SD-Turbo 权重仍未装完。

### 4.1 OSEDiff（Wu et al., NeurIPS 2024）

- 论文：*One-Step Effective Diffusion Network for Real-World Image Super-Resolution*
- 实现：<https://github.com/cswry/OSEDiff>

核心机制：把 LQ 作为扩散起点，而不是从纯噪声起步；用一步采样代替常规 20–50 步；LoRA 把 SD 2.1-base 拉向复原；潜空间 VSD（variational score distillation）约束输出分布。公开推理脚本提供 `vae_encoder_tiled_size` / `vae_decoder_tiled_size` / `latent_tiled_size`，训练显存需求在公开材料中为 24 GB 量级。

与本题的对应关系：

- 「从 LQ 起步 + 一步」同时压低幻觉来源和 63 tile 的步数乘子。
- 赛题二把 OSEDiff 时延当作加速比基准，说明组委会承认这条技术线，但不构成赛题一的分数承诺。
- 原论文面向超分。本题要求分辨率不变，正确用法是 **upscale = 1**，输出尺寸必须等于输入。按 \(4\times\) 跑会直接违反规则。

本机实现：`src/models/osediff.py`，backend 名 `osediff`。权重（官方 LoRA + `Manojb/stable-diffusion-2-1-base` fp16）不在本仓库，下载见 `weights/README.md`。未加载 RAM / DAPE，prompt 来自场景控制器。`upscale=1`，4K 走仓库既有 512/64 分块。官方 HuggingFace 下 UNet 时出现 WinError 10054/10060，该文件改由 `hf-mirror.com` 拉完。分数见第 6.6 节。

### 4.2 SeeSR

- 论文：*SeeSR: Towards Semantics-Aware Real-World Image Super-Resolution*
- 实现：<https://github.com/cswry/SeeSR>

RAM 提取语义标签再条件化 Stable Diffusion，常见采样约 **50 步**。在本机分块设定下，前向次数约为 \(63\times 50=3150\) 次 SD 级 UNet，数量级高于 Lite 的 \(63\times 12=756\) 次且单次 FLOPs 远大。更关键的是条件来自开放词汇标签：对「试卷 / 书脊 / 罗马钟」这类必须逐笔画、逐角度对齐的对象，语义正确与像素正确不是同一目标。本阶段因此不把它列为第一基线。该判断未经本机出分验证。

### 4.3 DiffBIR 与 SUPIR

DiffBIR：SwinIR 去退化 + IRControlNet，常见约 50 步。作者仓库 issue 给出 640² 约 11 GB 的显存量级；8 GB 只能更细地切块，100 张 4K 不具备日常迭代条件。

SUPIR：SDXL 级先验，参数量与显存都高于 SD 2.x 线，不适合作为 8 GB 上的可复现起点。

两者与 SeeSR 共享同一类风险：密叶上可能得到更「好看」的纹理，但文字与指针的幻觉机制相同。本阶段未跑。

### 4.4 SD-Turbo img2img

通用文生图蒸馏模型，不是复原模型。条件是文本与 `strength`，不是退化估计。`benchmark.json` 记录：下载 `stabilityai/sd-turbo` 时 HuggingFace Xet 返回 **401 Unauthorized**，探测中止。即使权重可用，其生成先验与 case1/2/5 的字形、指针约束也不匹配。

### 4.5 筛选结果汇总

| 方案 | 本阶段结论 | 起点 | 典型步数 | 8 GB 上的可行性（机制） | 文字 / 钟表风险 | 官方验证集实测 |
| --- | --- | --- | --- | --- | --- | --- |
| OSEDiff 裸输出 | 生成过强，不能当提交 | LQ 潜变量 | 1 | 3.03 GB，28.9 s/张 | case1 掉 8.1 dB | **23.216 / 0.740** |
| OSEDiff + fuse | 与 LQ 持平，case2/5 略升 | 同上，残差被钳 | 1 | 同左 | 文字仍 −0.47 dB | **28.030 / 0.781** |
| SeeSR | 不作为第一基线 | 噪声 + 语义 | ~50 | 63×50 次 SD 前向 | 高（标签改写） | 无 |
| DiffBIR | 不作为第一基线 | 去退化 + 控制 | ~50 | 640² 约 11 GB | 高 | 无 |

## 5. 可运行基线：方法

流水线为：

```text
LQ
  → 场景路由（验证集为人工 override）
  → 场景控制器（strength / prompt）
  → LiteCondUNet，按 tile 做条件 DDIM
  → Hann 融合，强制原分辨率
  → fidelity fuse
  → JPEG 写出
```

### 5.1 Lite 条件 DDPM

`LiteCondUNet` 输入为 \(\mathrm{concat}(x_t, x_{\mathrm{LQ}})\)（6 通道），预测噪声 \(\varepsilon_\theta\)。宽度 `base=32`，三级下采样残差 + 中间块，时间嵌入为正弦位置编码。这是 Diffusion 原生结构，满足赛题架构约束，但容量远小于 SD 2.x。

推理：按 `strength` 把 LQ 加噪到

\[
t_0 = \mathrm{clip}\bigl(\lfloor T\cdot s\rfloor,\,1,\,T-1\bigr),\quad T=50,
\]

再 DDIM 12 步回到 \(t=0\)。\(s\) 越大，起点越接近纯噪声，生成自由度越高。当前取值对应 \(t_0\in\{9,10,11,12,14,15\}\)（text→plant）。文字与钟表使用较低 \(s\)，植物与鸟类较高，是对「可改纹理 / 不可改符号」的先验，不是验证集上搜出来的最优。

Lite 权重来自合成几何图上约 400 step 的短训，**没有**用官方 5 对 GT 微调；权重文件不在本仓库，见 `weights/README.md`。

### 5.2 残差限幅融合

\[
y = \mathrm{clip}\Bigl(x + \alpha\cdot\mathrm{clip}(\hat{x}-x,-\Delta,\Delta),\,0,\,255\Bigr).
\]

当 \(\alpha=0.25,\Delta=12\) 时，单通道每像素相对 LQ 的最大改动为 \(\alpha\Delta=3\) 个灰阶。若所有像素都取到该上界，则 \(y\) 相对 \(x\) 的 PSNR 下界为

\[
10\log_{10}(255^{2}/9)\approx 38.59\,\mathrm{dB}.
\]

因此 fuse 后的输出在 \(\ell_\infty\) 意义下被锁在 LQ 的 3 灰阶管内。它解释了第 6 节中「融合后均值贴近 LQ」的现象，也说明这条基线 **几乎没有把 case4 从 18 dB 拉起来的能力**：3 灰阶改不动油画级模糊。

对照实验中的另外两个后处理：

- **高通结构锁**：\(y = x_{\mathrm{low}} + (\hat{x}-\hat{x}_{\mathrm{low}})\)，保留 LQ 低频、只取预测高频。若 \(\hat{x}\) 的高频是颗粒，该操作会把颗粒贴回原图。
- **LAB 色彩对齐**：把预测的 LAB 通道均值 / 方差匹配到 LQ。官方验证集上 LQ 与 GT 已有色偏差；强行拉回 LQ 色统计会增大对 GT 的误差。

### 5.3 与「拷贝 LQ」的关系

拷贝 LQ 在 PSNR 上最优（28.034），但不满足「必须 Diffusion」的提交约束。Lite + fuse 走完整的条件扩散前向，再用 \(\ell_\infty\) 残差管回到 LQ 邻域。它证明流水线可运行，不证明增强已经发生。

### 6.2 后处理消融的读法

在 \(\hat{x}\) 固定为裸 Lite 的前提下：

- 高通单独几乎不修复（27.674 vs 27.649），说明有害成分主要在高频，结构锁会保留它。
- \(\alpha\) 从 0.25 增到 0.55，均值单调下降（28.004 → 27.970 → 27.896）。更大的残差预算把更多颗粒放进 \(y\)。
- 「高通 + fuse」和「fuse + LAB」都低于「只做最紧的 fuse」。LAB 在这 5 张上对 GT 有害，与 2.2 节「对齐后的 LQ 也不能当对照」一致。

因此，当前冻结配置关闭 `color_match` 与 `lock_content`、只保留最紧 fuse，是消融结果，不是默认美学选择。

端到端 27.982 比内存 fuse 28.004 低 **0.021 dB**，量级符合 JPEG 再编码，不是另一次模型退化。

## 7. 讨论

### 7.1 指标角色

在 \(n=5\) 且官方公式未知时，PSNR 的有效用法是 **单侧哨兵**：相对 LQ 下跌超过约 0.1 dB，几乎总是引入了噪声或结构漂移（裸 Lite −0.386 dB、LAB −0.104 dB 均属此类）。它不能当「更锐」的代理——case4 需要的是高频纹理恢复，那会先表现为与 LQ 的残差变大，PSNR 对 GT 是否上升取决于残差是否落在 GT 方向。当前 fuse 把残差上界设为 3 灰阶，等于主动放弃这条路径。

### 7.2 Lite 失败的原因不在「不是 Diffusion」

Lite 满足架构约束，也从 LQ 加噪起步。失败来自 **容量与训练分布**：`base=32` 的 UNet 在 400 step 合成几何上只能学到非常局部的去噪，遇到试卷彩边、书脊虚焦、密叶油画糊时，反向过程的 \(\varepsilon_\theta\) 没有对应的复原方向，于是在已清晰区域（尤其 case3）写出颗粒。fuse 是在分布外推失败之后的 \(\ell_\infty\) 补救，不是训练成功的证据。

### 7.3 方案筛选的不确定性

OSEDiff 现在有本机分数，但命题要拆开：裸模型 **劣于** Lite 与 LQ（−4.82 dB）；fuse 后均值与 LQ 持平（−0.005 dB），SSIM 略高于 LQ（0.781 vs 0.778），并在 case2/5 上给出本阶段最大正 Δ。这不是「OSEDiff 整体优于 Lite」，而是「生成残差被钳位之后，书脊与钟面有可测的像素收益，试卷与海鸟仍赔」。SeeSR / DiffBIR / SUPIR 的排除仍是机制命题。

### 7.4 命名与对照上的两个偏差源

1. 验证集 / 测试集共享 `caseN` stem。把验证集 override 套到测试集会把试卷策略打到另一张图上。
2. 经过 LAB 的 identity 不再是科学下限。任何「相对 identity 涨分」的表述，必须先声明 identity 是否等价于原始 LQ。

## 8. 结论

1. 官方验证集不是均衡基准。提质的像素误差预算集中在 case4；case1/2/5 考查符号与几何一致性；case3 考查「能不能不做多余生成」。
2. 8 GB 上可以跑通 OSEDiff 推理（3.03 GB，约 29 s/张）。裸输出均值 23.22，不能提交；+fuse 后 28.030 / 0.781，与 LQ 持平，case2/5 略升，case1/3 仍赔，case4 不动。
3. 本地 Lite + 残差限幅仍是更轻的工程基线：端到端 **27.982 / 0.775**，0.31 GB。质量上不构成上限；OSEDiff+fuse 的均值略高于这条 Lite 基线，但代价是约 10× 显存。
4. 后处理消融（Lite）与 OSEDiff 裸/fuse 对照一致：在当前 \(\hat{x}\) 质量下，不限幅就会漂离 LQ。保真与「看起来更锐」在 case4 上仍未同时成立。

---

## 9. 建议

以下不是测量结果，只是由第 6–8 节推出的后续工作方向。

1. 对照列应是 **LQ 28.034 / 0.778**、**Lite 端到端 27.982 / 0.775**、**OSEDiff+fuse 28.030 / 0.781**。不要拿裸 OSEDiff 或裸 Lite 当质量参照。
2. 若继续用 OSEDiff：先处理 case1 文字跌分（降 strength / 区域 fuse），不要先放大 \(\alpha\)。case4 需要能突破 3 灰阶管的残差，否则密叶不会动。
3. 官方 RAM/DAPE 与当前场景 prompt 是否改变 case1/3，应单独做一列，不要和本次分数混报。
4. 不要用这 5 对 GT 微调后再报同一验证集。测试集场景应单独标注。
5. 提交次数每周 1 次。OSEDiff+fuse 相对 LQ 只有 −0.005 dB，用它交榜主要检查格式，不是质量跃迁。
6. 人脸模块无法在本验证集上证伪或证实。
